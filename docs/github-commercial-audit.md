# GitHub commercial-content audit

Reviewed on 2026-09-26 against the 29 public repositories visible on
`github.com/BoltTaha`. This file records why the portfolio promotes a focused
selection instead of presenting every repository as client work.

## Selection criteria

A repository is strong commercial evidence when it demonstrates a costly
client problem, an implemented end-to-end workflow, inspectable source or test
evidence, a current buyer search intent, and a path from the existing project
to a production engagement. Educational status is stated where applicable.

## Primary commercial evidence

- **Rabt Code Intelligence**: AST and dependency-graph context selection for
  coding agents. The public evaluation supports a technical article about
  reducing repository context while measuring answer quality.
- **MCP Data Analyst**: guarded PostgreSQL access through MCP and REST, with
  schema retrieval, AST validation, read-only execution, limits, statistics,
  and charts. This is the clearest enterprise AI/backend reference project.
- **QR Payment Verification**: asynchronous receipt intake, exact and
  perceptual duplicate checks, structured extraction, risk signals, and human
  review. The portfolio describes it as review assistance rather than proof of
  financial settlement.
- **Context Window Compressor**: tiered conversation memory, summarisation,
  fact extraction, and context rebuilding. It supports LLM-memory and agent
  reliability conversations when its experimental limits are stated.
- **Eventora Planner**: Flutter, Firebase authentication, user-scoped storage,
  notifications, and reviewed structured AI input. It demonstrates a reusable
  mobile workflow rather than claiming paid adoption.
- **Computer-vision and document-processing client cases**: these are the
  strongest evidence for video analytics and large-batch image-processing
  services because they connect engineering decisions to real operator needs.

## Supporting evidence

SnapTeX, Automated Color Grading, Crisis Intelligence, and the distributed-data
repositories demonstrate useful technical range. They remain case studies or
skills evidence, but they should not displace the primary commercial projects
in the opening portfolio narrative.

## Repositories intentionally not promoted as paid-service case studies

Course labs, semester assignments, introductory management systems, Tetris,
data-structure visualisers, and the Gentoo guide show learning history. They do
not currently provide stronger buyer evidence than the selected AI systems.
Keeping them on GitHub is reasonable; placing all of them on the portfolio
would weaken the site's specialist positioning.

## Content published from this audit

The public Insights collection now includes source-backed articles on:

- graph-based context selection for LLM coding agents;
- safer text-to-SQL and MCP analytics systems;
- payment-receipt review and duplicate detection;
- AI-assisted Flutter/Firebase application architecture;
- basketball highlight detection; and
- large scanned-document preprocessing.

Each article starts with a direct answer, uses descriptive headings, includes
questions clients ask, links to related evidence, and renders BlogPosting plus
FAQPage structured data. These features improve machine readability and search
coverage, but they do not guarantee rankings, AI citations, leads, or sales.
